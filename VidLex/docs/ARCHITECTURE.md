# VidLex: архитектура и технические решения

## 1. Кратко

VidLex — WPF-приложение на .NET Framework 4.8 (MVVM). Вся логика вынесена в библиотеку `VidLex.Core`, которая
не зависит от интерфейса. Тяжёлые операции выполняют внешние процессы:

```
┌──────────────────── VidLex.exe (WPF, .NET Framework 4.8) ────────────────────┐
│ Views (XAML) ⇄ ViewModels (MVVM)                                            │
│        │                                                                     │
│        ▼                                                                     │
│ VidLex.Core: QueueProcessingService ─► JobProcessor ─┬─► MediaProbeService   ─┼─► ffprobe.exe
│              (очередь, пауза, стоп)   (одно видео)   ├─► AudioExtraction     ─┼─► ffmpeg.exe
│                                                      ├─► SilenceDetection    ─┼─► ffmpeg.exe (silencedetect)
│                                                      ├─► WhisperCppEngine    ─┼─► whisper-cli.exe (по фрагментам)
│                                                      ├─► SegmentMerger + TextCorrectionService (Hunspell ru_RU)
│                                                      └─► TranscriptExportService ─► TXT (UTF-8, атомарно)
│ LoggingService · SettingsService · ProgressEstimationService · QueueStateStore │
└──────────────────────────────────────────────────────────────────────────────┘
```

Распознавание работает в отдельном процессе (CLI). Сбой или нехватка памяти в нативном коде whisper.cpp
завершает только `whisper-cli.exe`: задание получает статус «Ошибка», очередь продолжается, интерфейс не падает.
Дочерние процессы привязаны к Windows Job Object с флагом `KILL_ON_JOB_CLOSE`, поэтому при аварийном
завершении VidLex они тоже закрываются.

## 2. Выбор технологий

### 2.1. Движок распознавания

| Вариант | Русский язык | Совместимость с .NET Framework 4.8 | Почему выбран или нет |
| --- | --- | --- | --- |
| **whisper.cpp, процесс `whisper-cli`** | да, многоязычные модели Whisper | любая (обмен через CLI и JSON) | **выбран**: локально, без Python, официальные сборки под Windows (CPU, CUDA), изоляция сбоев, прогресс и таймкоды токенов в JSON |
| Whisper.net (NuGet-обёртка whisper.cpp) | да | библиотека для .NET Standard 2.0 | нативный код в процессе UI: его сбой закрывает приложение; версия обёртки жёстко привязана к нативным пакетам |
| faster-whisper (Python, CTranslate2) | да | только через отдельный Python | пришлось бы поставлять интерпретатор Python и зависимости |
| Vosk | есть русские модели | есть .NET-привязки | без пунктуации и регистра «из коробки», качество на свободной речи ниже Whisper |
| Облачные API | да | HTTP | противоречит требованию автономной работы: видео ушли бы на сторонний сервер |

Проверка совместимости проведена на деле, а не по описаниям:
- `whisper-cli` 1.8.5 собран из исходников и прогнан на русской речи;
- изучен его код: формат JSON (`-ojf`), строки прогресса, файл ответов `@file`;
- выявлена особенность Windows. `whisper-cli` получает `argv` в ANSI-кодировке, а путь к модели
  интерпретирует как UTF-8 (`whisper.cpp`, `whisper_init_from_file_with_params_no_state`). Поэтому VidLex
  передаёт все аргументы через файл ответов в UTF-8, а аудиофрагменты называет латиницей относительно рабочей папки.

### 2.2. Остальные компоненты

| Задача | Решение | Обоснование |
| --- | --- | --- |
| Интерфейс | WPF, .NET Framework 4.8, MVVM | требование ТЗ; входит в Windows 10 (1903+) и Windows 11 |
| Извлечение аудио | FFmpeg (`ffprobe` + `ffmpeg`) | читает все форматы из ТЗ; прогресс через `-progress pipe:1` |
| Поиск пауз | `ffmpeg -af silencedetect` | точки разреза длинных записей, пунктуация, фильтр галлюцинаций |
| Орфография | WeCantSpell.Hunspell + словарь ru_RU (LibreOffice, А. Лебедев) | управляемый код под .NET Standard 2.0, полная морфология русского через аффиксы |
| Настройки, состояние | JSON (Newtonsoft.Json) | надёжен на .NET Framework, `ObjectCreationHandling.Replace` для списков |
| Выбор папок и файлов | Ookii.Dialogs.Wpf | современные системные диалоги Windows вместо устаревшего дерева WinForms |
| Журнал | собственный `LoggingService` | без внешних зависимостей: фоновая запись, ротация по дням и размеру, буфер для UI |

Внедрение зависимостей сделано через конструкторы: интерфейсы в `Abstractions/Contracts.cs`, сборка графа —
в `VidLexHost` (общий корень композиции для WPF и CLI). Отдельный DI-контейнер не нужен: граф небольшой и статичный.

## 4. Обработка одного видео (JobProcessor)

| Этап | Статус | Доля прогресса | Источник прогресса |
| --- | --- | --- | --- |
| Проверка доступа и решения о сохранении | Подготовка аудио | 0–1 % | — |
| `ffprobe`: длительность, дорожки | Подготовка аудио | 1 % | — |
| Проверка свободного места, `ffmpeg` → WAV 16 кГц моно | Подготовка аудио | 1–8 % | `out_time_us` от FFmpeg (подтверждённый) |
| Поиск пауз | Подготовка аудио | 8–10 % | — |
| Распознавание по фрагментам | Распознавание | 10–92 % | таймкоды сегментов и `progress = N%` от whisper.cpp |
| Склейка, пунктуация, орфография | Обработка текста | 92–96 % | — |
| Атомарная запись TXT | Сохранение | 96–100 % | — |

Ошибки внутри задания (повреждённый файл, сбой whisper, нехватка места, недоступная папка) превращаются в статус
«Ошибка» с понятным текстом; технические подробности (код возврата, командная строка, хвост stderr) уходят в журнал.
Если TXT не удалось записать, расшифровка сохраняется в `%LocalAppData%\VidLex\Recovered`, путь указывается в ошибке.

### 4.1. Длинные записи

`ChunkPlanner` делит аудио на фрагменты около заданной длины (по умолчанию 600 с). Граница ставится в середину
паузы в окне от «цель − 90 с» до «цель + 30 с»: предпочтение длинным паузам, штраф за удаление от цели.
Если пауз нет (музыка, шум), фрагменты режутся жёстко с перекрытием 4 с. На таком стыке `SegmentMerger` ищет
самое длинное совпадение последовательностей слов в зоне перекрытия (два и больше слов либо одно слово от
4 букв) и берёт повтор один раз. Если совпадения нет, слова делятся по середине перекрытия по времени.

После каждого фрагмента результат пишется в контрольную точку (`Temp\job-<id>\checkpoint.json`). После сбоя
или закрытия программы обработка продолжается со следующего фрагмента, если не изменились файл, модель,
длина фрагмента и дорожка.

### 4.2. Параметры whisper.cpp

`-l ru -oj -ojf -pp -bs 5 -mc 0` плюс `-t N`, `-ng` (без GPU) и `--prompt` (пользовательские термины).
Значения по умолчанию выбраны по замерам (см. TESTING.md, раздел 3):
- `-mc 0` (не переносить текстовый контекст между 30-секундными окнами) снизил WER на зашумлённой лекции
  с 0,79 до 0,57, на чистой — с 0,42 до 0,41;
- подсказка из конца предыдущего фрагмента провоцировала зацикливание («Продолжаем оборудование» ×5) и потерю
  около 30 % слов фрагмента, поэтому по умолчанию она выключена.

## 5. Постобработка текста

`TextCorrectionService` работает со **словами с временем** (из токенов whisper.cpp), а не со строкой. Поэтому
соседние фразы физически не могут склеиться (между словами всегда пробел), а у каждой фразы известно время
начала для меток. Порядок шагов:

1. Удаление символов U+FFFD (повреждённый UTF-8 от модели); сегменты, набранные ЗАГЛАВНЫМИ, переводятся
   в обычный регистр (аббревиатуры вроде «МВД» сохраняются).
2. Фильтр галлюцинаций: титры субтитров («Субтитры сделал DimaTorzok» и т. п.) удаляются всегда. Фразы вроде
   «Продолжение следует», «Спасибо за просмотр» удаляются только если сегмент на 80 % и больше лежит в тишине
   (по данным FFmpeg). Подряд идущие повторы одного сегмента из трёх и более слов (три раза и больше)
   сводятся к одному вхождению.
3. Удаление пометок неречевых звуков: `[музыка]`, `(смех)` (настраивается).
4. Разделение склеенных токенов («фраза.Следующая») с защитой адресов и чисел; присоединение отдельно стоящих
   знаков к слову; нормализация повторов («,,» → «,», «!!» → «!», «,.» → «.»).
5. Границы сегментов. Если сегмент закончился без знака, а следующий начинается с заглавной нарицательного
   слова, или после паузы ≥ 700 мс, или со слова-связки — ставится точка. Продолжение со строчной буквы точку
   не получает (конец сегмента ≠ конец предложения). После запятой заглавная у нарицательного слова
   заменяется строчной.
6. Слитные фразы внутри сегмента: точка перед словом-связкой («далее», «затем», «после этого», «кроме того»…),
   если перед ним содержательное слово (не предлог, не союз, не местоимение), в предложении уже не меньше
   3 слов и после связки идут ещё минимум 2 слова. Также точка ставится перед нарицательным словом
   с заглавной буквы и после длинной паузы перед заглавной.
7. Орфография (Hunspell ru_RU, с учётом ё/е). Исправляются только слова со строчной буквы, кириллица,
   длина от 5 букв, которых нет ни в словаре, ни в пользовательском списке. Принимается единственный вариант
   на расстоянии одной правки (Дамерау — Левенштейн). Если вариантов несколько — единственный, сохраняющий
   окончание. Неизвестные слова (имена, термины, англицизмы) не меняются.
8. Сборка предложений: заглавная в начале, сокращения («т. е.», «г.») не обрывают предложение,
   в конце записи ставится точка.

Слова не добавляются и не удаляются, кроме пометок неречевых звуков и отфильтрованных галлюцинаций. Каждое
удаление пишется в журнал. Языковая модель для свободного переписывания текста не используется.

## 6. Временные метки и формат TXT

- Метки выключены: сплошной текст, абзац начинается после паузы ≥ 3 с (настраивается).
- Метки включены, период 0: `[ЧЧ:ММ:СС] Фраза.` — по строке на фразу; время — начало фразы в исходном видео
  (смещение фрагмента учитывается).
- Метки включены, период N > 0: фразы собираются в абзацы, метка ставится перед первой фразой, начавшейся не
  раньше чем через N секунд после предыдущей метки. Это **период отображения**, он не влияет на нарезку аудио
  для распознавания (за неё отвечает «Длина фрагмента»).
- Кодировка UTF-8 (по умолчанию с BOM), переводы строк CRLF, запись через временный файл и `File.Replace`.

## 7. Имена файлов и коллизии

- **Рядом с видео:** `Урок 01.mp4` → `Урок 01.txt`. Если в одной папке есть `Урок 01.mp4` и `Урок 01.mkv`,
  первый по естественной сортировке получает `Урок 01.txt`, второй — `Урок 01 [mp4].txt`.
- **Отдельная папка:** уникальное имя — как есть; при совпадении добавляется относительный путь:
  `Урок 01 (Курс - Модуль 2).txt`; при полном совпадении — расширение, затем `(2)`, `(3)`.
  План имён строится для всей очереди заранее (детерминированно).
- Скрытый `.vidlex-manifest.json` в папке результатов связывает TXT с исходным видео. Файл, созданный
  не VidLex, не перезаписывается никогда: результат получает новое имя, событие пишется в журнал.
- Политики для существующего результата: «Пропускать» (статус «Пропущено», не «Ошибка»), «Перезаписывать»,
  «Сохранять как новый файл».

## 8. Очередь, пауза, остановка

- По умолчанию видео обрабатываются последовательно (1 задание). whisper.cpp и так использует все ядра,
  параллельные задания делят те же ресурсы. Можно включить до 4 заданий, тогда потоки делятся между ними.
- **Пауза** настоящая: процессы `ffmpeg`/`whisper-cli` замораживаются (`NtSuspendProcess` на Windows, `SIGSTOP`
  в тестах на Linux), новые этапы и задания не начинаются, учёт времени останавливается. Если заморозить процесс
  не удалось, это пишется в журнал, а пауза наступает после текущего этапа (состояние «Пауза: ожидание…»).
- **Остановка** завершает процессы и удаляет временные файлы текущего задания, остальные остаются «Ожидает».
  При закрытии окна во время обработки контрольные точки сохраняются, а при следующем запуске программа
  предлагает восстановить очередь.

## 9. Оценка времени

`ProgressEstimationService` считает скорость как активное время обработки, делённое на длительность аудио.
Берётся среднее по завершённым заданиям, взвешенное по длительности, и смешивается с экспоненциально
сглаженной скоростью последних заданий. Пока нет ни одного завершённого видео, используется скорость
распознавания текущего видео (после 30 с аудио и 10 с работы); до этого показывается «Расчёт времени…».
Показываемый остаток сглаживается: естественный обратный отсчёт плюс 15 % новой оценки на каждом обновлении.
Значение округляется (до 5 с, 15 с, минуты, 5 минут) и всегда выводится со знаком «≈».
