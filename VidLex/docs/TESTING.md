# VidLex: тестирование

## 1. Что и как проверяется

| Уровень | Где | Что проверяет |
| --- | --- | --- |
| Модульные тесты | `tests/VidLex.Core.Tests` (xUnit, 89 тестов) | постобработку текста, планирование фрагментов и склейку, разбор ffprobe, silencedetect и JSON whisper.cpp, экспорт и коллизии имён, настройки, журнал, поиск видео, оценку времени, очередь (на подставных сервисах) |
| Сквозные тесты | `tests/e2e/e2e_check.py` + `VidLex.Cli` | настоящий FFmpeg и whisper.cpp на русской речи (espeak-ng) в 12 форматах, 7 сценариев, 43+ проверки |
| Интерфейс | `scripts/ci/Gui-Smoke.ps1` (Windows, UI Automation) | запуск `VidLex.exe`, навигация, подписи разработчика, обработка папки из GUI, корректное закрытие, журнал, скриншоты |
| CI | `.github/workflows/vidlex-windows.yml` (windows-latest) | сборка, модульные тесты под net48 и net8.0, установка компонентов скриптом, E2E на net48, GUI, Release-ZIP |

Запуск модульных тестов: `dotnet test tests/VidLex.Core.Tests`.
Сквозные: `python tests/e2e/e2e_check.py --cli <VidLex.Cli> --media tests/e2e/media --work <папка> --model <ggml-*.bin> [--whisper …]`.
Тестовые видео пересоздаются скриптом `tests/e2e/make_media.sh` (нужны espeak-ng и ffmpeg).

**Об оценке качества распознавания.** Тестовая речь синтезирована espeak-ng: у неё роботизированный голос,
и модель small ошибается на нём заметно чаще, чем на живой речи. Пороги WER в сквозных тестах проверяют,
что содержание действительно распознано (не пусто и не мусор), а не точность модели. На двух фразах
(«Для каждого видео…», «Если включены временные метки…») модель small ошибается почти во всех словах. То же
видно при прямом запуске `whisper-cli` без VidLex, поэтому для этих роликов проверяется только формат файла.

## 3. Замеры, на которых основаны параметры по умолчанию

Linux, 4 ядра, whisper.cpp 1.8.5 (CPU), модель Whisper small: веса CTranslate2 int8 сконвертированы в ggml f16,
т. к. в окружении разработки Hugging Face был недоступен. Речь — espeak-ng. WER — доля ошибок по словам.

| Аудио | По умолчанию whisper.cpp | `-mc 0` | Подсказка «хвост предыдущего фрагмента» |
| --- | --- | --- | --- |
| Фрагмент 79 с (142 слова) | 0,556 | 0,528 | 0,641, потеряно 41 слово из 142 |
| Лекция 2:19, чистая (249 слов) | 0,422 | 0,406 | — |
| Лекция 2:19, розовый шум (249 слов) | 0,787 | 0,574 | — |

Вывод: по умолчанию `-mc 0`, подсказка «хвостом» выключена (оба параметра есть в настройках).
После этих изменений распознавание лекции фрагментами по 60 с через VidLex дало WER 0,42 и 236 слов из 249.
Это на уровне распознавания файла целиком, то есть склейка фрагментов не теряет и не дублирует текст.

## 5. Известные ограничения

- **Качество** определяется моделью: на CPU модели large работают в разы медленнее small. Шумные записи,
  музыка и несколько одновременных говорящих снижают точность; разделения по говорящим нет.
- **Пунктуацию** в основном расставляет сама модель Whisper. VidLex исправляет форму (границы сегментов,
  слитные фразы, повторы знаков) по правилам, а не языковой моделью: сложные случаи (вводные слова,
  запятые в сложных предложениях) остаются как их выдала модель.
- **Орфография** исправляет только однозначные опечатки. Ошибки распознавания, дающие существующее слово
  («примерам» → «премьерам»), словарём не обнаруживаются.
- **Пауза** замораживает процессы через `NtSuspendProcess` — недокументированную, но давно стабильную функцию
  Windows (её используют Process Explorer и монитор ресурсов). Если заморозка не удалась, пауза наступает после
  текущего этапа, это видно в интерфейсе.
- **Нехватка места** проверяется заранее по длительности видео. Сценарий с реально заполненным диском
  автоматически не тестировался.
- **whisper-cli** нужен версии 1.8 или новее (передача аргументов через файл ответов).
- Модульные тесты класса `PausableStopwatch` и паузы зависят от таймеров. На сильно загруженной машине
  возможны редкие ложные срабатывания.
