# FastGen — редактор шаблонов размножения

WinForms, .NET Framework 4.7.2, открывается в Visual Studio 2019 (`FastGen.sln`).

Рядом с `FastGen.exe` программа ищет:

| Файл | Что это |
|---|---|
| `DICT.DBF` | большая база TextExpert (dBASE, cp866). BDE не нужен, читается в фоне |
| `GoldBase.txt` | база, собранная из ваших шаблонов (вкладка «Сборщик») |
| `UserBase.txt` | **новое:** «Моя база», куда пишет Ctrl+PgDn. Главнее всех остальных баз |
| `syn_usage.txt` | какие синонимы вы уже выбирали (частые идут первыми и выделены жирным) |
| `syn_rejected.txt` | **новое:** синонимы, которые вы убрали из конструкции, — больше не предлагаются для этого слова |
| `GoldBase_manual.txt` | **новое:** журнал наборов, собранных вами вручную; при «Сборке» GoldBase они не теряются |
| `Context.bin` | **новое:** пары соседних слов из `ResultDB.txt`, строится сам при первом запуске (несколько секунд) и при «Сборке» |
| `BadWord.txt`, `Exceptions.txt` | фразы, которые не трогать, и замены вида `рф=РФ` |
| `FastGen.ini` | настройки: последний файл, число синонимов, DICT вкл/выкл. Ключ `ProgonsRoot=` меняет папку `m:\PROGONS` |

## Как работать: размножение одной клавишей

1. Вставьте текст во вкладку «Размножение» (Ctrl+V вставляет только текст, без форматирования).
2. Нажмите **F5**: все слова и фразы, для которых есть синонимы, станут `{слово|синоним|…}`.
   Если что-то выделено, обрабатывается только выделенное. Существующие `{…}`, `[…]`, HTML-теги и ссылки не трогаются.
   Сколько синонимов F5 ставит в одну конструкцию, задаёт поле «Синонимов в F5» (на ручной выбор не влияет); галочка «DICT.DBF» подключает большую базу.
3. Курсор встаёт на первую конструкцию, а справа появляется список её вариантов. Дальше:
   * **F3 / Shift+F3**: следующая / предыдущая конструкция;
   * **↑/↓**: перейти в список, **Пробел** снимает или ставит вариант, **Enter** правит его, **Delete** удаляет;
   * **Ctrl+Enter**: записать отмеченные варианты и перейти дальше;
   * **Ctrl+→ / Ctrl+← / F3** тоже сначала записывают отмеченное (если вы что-то отметили или сняли), а потом переходят;
   * **правый щелчок по варианту** стирает его: `{1|2|3}` → `{1|3}`, а если остался один вариант, скобки убираются;
   * **правый щелчок по исходному (жирному синему) варианту** снимает конструкцию и оставляет только его: `{даже|в том числе|также}` → `даже`;
   * **F4**: убрать конструкцию и оставить исходное слово;
   * **Ctrl+Z**: отменить (один F5 отменяется одним Ctrl+Z).
4. **F9** (пробная генерация) показывает случайный готовый текст, пробел даёт следующий.
   Внизу всегда видно число вариантов текста и ошибки скобок (щелчок по ошибке переносит к ней).

Ручной режим как в TextExpert тоже есть: **Ctrl+→ / Ctrl+←** ходят по словам и конструкциям,
справа подтягиваются синонимы (моя база, затем частые, затем GoldBase, затем DICT), отмеченные попадают в шаблон по Ctrl+Enter.
**Ctrl+PgDn** записывает отмеченный список в «Мою базу», **Ctrl+PgUp** перечитывает его. Все клавиши собраны в **F1**.

## Ваш ручной выбор пополняет базу

Каждый раз, когда вы записываете конструкцию (Ctrl+Enter или Ctrl+→ / Ctrl+← после изменений), программа:

1. **считает частоту**: каждому оставленному синониму +1 (`syn_usage.txt`). В списке справа рядом с ним
   появляется «×N», и чем чаще вы его выбирали, тем выше он стоит (сразу после «Моей базы»);
2. **пополняет GoldBase автоматически**: как только синоним выбран **6 раз** (больше 5), пара `слово|синоним`
   сама дописывается в `GoldBase.txt` (и в журнал `GoldBase_manual.txt`, чтобы «Сборка» её не стёрла).
   Внизу появится «GoldBase пополнена: …». Пары, набравшие 6 выборов раньше, добавляются при запуске программы.
   Порог меняется в `FastGen.ini`: строка `GoldMinUses=6`;
3. **запоминает отказы**: варианты, которые вы сняли из конструкции (или стёрли правым щелчком), больше не
   предлагаются для этого слова и в GoldBase не попадают.

## Готовые шаблоны пополняют ResultDB.txt

Когда вы закрываете программу (а также нажимаете «Очистить» или открываете другой файл), сохранённый шаблон
дописывается в конец `ResultDB.txt`, а его пары соседних слов сразу добавляются в проверку соседей.
Так каждый ваш размноженный текст улучшает следующие.

* Если файл для шаблона **не выбран**, при закрытии появится вопрос:
  **Да** — выбрать файл и сохранить; **Нет** — закрыть без сохранения (в ResultDB ничего не попадёт);
  **Отмена** — вернуться к тексту.
* Один и тот же текст дважды не дописывается (отпечатки добавленных — в `ResultDB.txt.added`).
* Не дописываются тексты без конструкций `{…}` и с ошибкой скобок.

## Читаемость: как F5 выбирает синонимы

Синоним из GoldBase или DICT подходит к слову «вообще», но не к *этому* месту в тексте:
«собирать кубик → копить кубик», «материалы → пиломатериалы», «решения паритета → выводы паритета».
Поэтому F5 теперь берёт синоним, только если выполнены все условия:

1. **Проверка соседей** (галочка «Проверять соседей»). Синоним должен хотя бы раз стоять рядом
   с теми же левым и правым словами в ваших готовых шаблонах (`ResultDB.txt`, 22 МБ ≈ 490 тыс. пар).
   «научиться складывать кубик» встречалось — берём; «копить кубик» не встречалось — нет.
   Если соседей нет (слово между запятыми), берутся только синонимы, которые вы сами выбирали ≥ 2 раз.
   Проверка главнее поля «Синонимов в F5»: не подошёл по соседям — не берётся, даже если вы его часто выбирали
   (обходит проверку только «Моя база»). Поле лишь ограничивает, сколько *подошедших* синонимов поставить.
   Если `ResultDB.txt` нет рядом с программой, проверять не по чему — F5 предупредит об этом и спросит, продолжать ли.
2. **Не трогаются** слова с заглавной в середине предложения (Фишер, Фридрих, Москва), АББРЕВИАТУРЫ (ТОП),
   слова с цифрами (2х2, 1080p), латиница, местоимения и служебные слова (кто, который, он, для…),
   а также варианты только из служебных слов («для тех → для»).
3. **Ваши отказы запоминаются.** Сняли вариант в конструкции и нажали Ctrl+Enter — пара попадает в
   `syn_rejected.txt` и больше не предлагается. Записали её в «Мою базу» (Ctrl+PgDn) — снова разрешена.
4. **«Моя база» главнее всего** и проверкой соседей не ограничивается.

Проверка соседей работает только при F5. В списке справа показываются все варианты из баз — выбирайте вручную.

На тексте про кубик Рубика это дало 19 конструкций вместо 50 и ни одной вроде «уканыкать сборку».
Чем больше ваших шаблонов в `ResultDB.txt` (вкладка «Сборщик» → Анализ → Сборка), тем больше
синонимов проходит проверку.

## Что исправлено

**Потеря данных**
* Если при выборе существующего файла стояла галочка «Заменить», файл сразу перезаписывался текстом из редактора, даже пустым. Теперь программа спрашивает, а при пустом редакторе просто открывает файл.
* «Вариант 1/2» (Shift+Delete / Shift+End) без выделения заменял весь шаблон одним перечислением. Теперь нужно выделение.
* Ctrl+Enter при выделенной фразе заменял её конструкцией *другого* слова: список синонимов оставался от прошлого слова.
* Щелчок мышью выделял слово целиком, и первая же набранная буква его стирала.
* Последние ~0,1 с правок не сохранялись при закрытии. Сохранение шло молча: если диска `M:` нет, надпись всё равно была «Автосохранение». Теперь показывается время сохранения или текст ошибки. Запись идёт через временный файл.
* Необработанная ошибка закрывала программу. Теперь она показывается, а работа продолжается.
* Файлы TextExpert в Windows-1251 открывались «кракозябрами». Теперь кодировка определяется автоматически.

**Ошибки**
* Ctrl+Z не работал: собственный Undo был написан, но не подключён, а встроенный в RichTextBox откатывал раскраску, а не текст. Теперь есть Ctrl+Z / Ctrl+Y на 300 шагов, набор текста группируется.
* Загрузка `DICT.DBF` в фоне показывала MessageBox из чужого потока, что могло приводить к зависанию или падению.
* `DICT.DBF` читался так, будто все поля записи — взаимные синонимы. В TextExpert первое поле — это слово, остальные — его синонимы. Старый разбор давал «мусорные» списки и съедал гигабайты памяти. Заголовок DBF теперь читается до маркера 0x0D, как требует формат.
* Подсветка ломалась на вложенных `{a|{b|c}}` (регулярка `\{[^}]+\}`), правый клик и «Вернуть» на вкладке «Быстрое размножение» тоже.
* Подсветка перекрашивала текст по одному символу через `Select()` каждые 100 мс: мерцание, прыжки прокрутки, тормоза на больших шаблонах. Теперь RTF строится одним проходом, а прокрутка и выделение сохраняются.
* «Сборка» в «Сборщике» сравнивала каждый новый набор со *всеми* предыдущими. На 22 МБ ResultDB это часы. Теперь она идёт по индексу слов: 256 тыс. конструкций обрабатываются примерно за 3 с, в фоне, окно не замирает. Поле «Файл базы» раньше игнорировалось, теперь используется.
* Регистр: «Удобная» превращалась в «Очень Удобная». Теперь заглавной становится только первая буква, а «Каждое Слово» сохраняется только для «Российская Федерация».
* Автоматическое размножение заходило в HTML-теги, ссылки и уже готовые конструкции (получались вложенные `{{…}}`). Числа («1080p», «2025») не считались словами.
* Из GoldBase для слова брался только *первый* набор, где оно встречается. Теперь объединяются все наборы, и чаще встречающиеся вместе синонимы идут первыми.
* `CheckedListBox` не поддерживает собственную отрисовку, поэтому жирные «частые» синонимы никогда не показывались. Список заменён на `ListView`.
* Мелочи: утечки шрифтов, дублирующийся код вкладок, ↑/↓ в тексте всегда уводили в список. Теперь в список ведут только когда слово выделено; при обычной каретке это простое перемещение по строкам.

## Структура

```
FastGen/
  Core/                 логика без интерфейса (её проверяют тесты)
    SpinSyntax.cs       разбор {…|…} и […], проверка скобок, подсчёт и генерация вариантов
    TextNav.cs          слова и переходы (конструкция — одно «слово», теги и ссылки пропускаются)
    SynonymStore.cs     все базы, DICT.DBF, приоритеты, «Моя база», частоты
    AutoSpinner.cs      размножение по F5
    RtfBuilder.cs       быстрая подсветка
    GoldBaseBuilder.cs  сборка GoldBase и сбор шаблонов из папки
    TextCase.cs         регистр, ротация, перечисления
    AppSettings.cs      FastGen.ini, чтение и запись файлов
  MainForm*.cs          окно и три вкладки
FastGen.Tests/          тесты логики: `dotnet test` (нужен .NET 8 SDK, в решение VS2019 не входит)
```

## Идеи на будущее

* **Проверка через ИИ (Claude API).** Отправлять предложение и список кандидатов, получать только подходящие
  по смыслу и уже в нужном падеже. Или сразу 3–5 перефразировок целого предложения вместо пословной замены —
  такие тексты читаются как написанные человеком. Нужен ключ API и интернет; текст на 1500 знаков стоит доли цента.

* **Морфология.** Сейчас синонимы ищутся по точной словоформе: «кино» и «кинофильмов» — разные ключи. С лемматизатором (например, Pymorphy через небольшой сервис или словарь OpenCorpora) можно искать по начальной форме и согласовывать синоним с падежом и числом. Это заметно уменьшит ручную правку.
* **Отметка «проверено».** F3 мог бы пропускать уже просмотренные конструкции, а строка состояния показывать «проверено 12 из 31».
* **Уникальность.** Сгенерировать 10–20 текстов и посчитать попарное сходство (шинглы), чтобы видеть, хватает ли вариантов.
* **Перенос правок из DICT в «Мою базу» пакетно.** После проверки текста одной кнопкой сохранить все выбранные варианты, чтобы следующий F5 сразу давал проверенные списки.
* **Вкладка «Сборщик» → «Моя база».** Уже сейчас частые синонимы (`syn_usage.txt`) учитываются первыми. Можно добавить фильтр «показывать только синонимы, выбранные ≥ N раз».
