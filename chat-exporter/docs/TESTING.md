# План тестирования

## Что уже проверено автоматически

| Набор | Команда | Что проверяет |
|---|---|---|
| Юнит-тесты (53) | `npm test` | Нормализация ChatGPT/Claude (ветки, правки, перегенерации, инструменты, вложения, изображения, цитаты, артефакты, сломанные цепочки), Markdown/HTML (CSP, экранирование, ссылки, изображения), проверка полноты, имена файлов и транслитерация, хеши, склейка снимков DOM (дубликаты, разрывы), расписание (дни недели, пропуски), выбор кандидатов для авто-режима, настройки, HTML→Markdown (jsdom), DOM-адаптеры, проверка целостности бэкапов |
| Проверка типов | `npm run typecheck` | JSDoc-типы всего `src/` (TypeScript `checkJs`) |
| E2E в Chromium | `xvfb-run -a npm run e2e` (Linux) или `npm run e2e` | Настоящее расширение в Chromium 1243 (Playwright 1.63). Сайты chatgpt.com и claude.ai **подменены** заглушками с синтетическими данными |

E2E-сценарий (проходит при локали `C` и `C.UTF-8`):

1. Пакетный экспорт чата ChatGPT и чата Claude в MD + HTML + PDF → 8 файлов (3 формата +
   `meta.json` на чат), статус «полный», PDF начинается с `%PDF-`, A4, тегированный, кириллица
   отображается.
2. «Экспорт текущего чата» из активной вкладки.
3. Повторный экспорт без изменений → `unchanged`, новых файлов нет.
4. Автозапуск после изменения чата «на сервере» → сохранён только изменившийся чат.
5. Резервный DOM-режим: эндпоинт отвечает 503, чат открыт во вкладке с **виртуализированным
   списком** из 60 сообщений (в DOM ~9) с повторяющимися «Ок» → собраны все 60, «Ок» не
   слиты, статус «полный, с предупреждениями».
6. Ответ из одного блока кода, помеченного как виджет (структура реального чата из отчёта пользователя)
   при форматах PDF + MD и выключенном `meta.json` → ровно 2 файла
   `ChatBackups/<название>/<название>_<дата>.pdf|.md`, блок кода в документе, статус «полный», без ложных предупреждений.
7. Пропущенный запуск (режим «спросить») → флаг `missedPending`, будильник пересоздан на будущее.
8. В консоли расширения нет ошибок.

> **Не проверено:** работа с настоящими chatgpt.com и claude.ai. Структура их внутренних
> данных взята из открытых проектов и может отличаться. Это нужно проверить вручную по плану ниже.

## Ручная проверка на реальных сайтах

Подготовка:
1. Установите расширение (см. README), откройте `chrome://extensions` → Chat Exporter →
   «service worker» → откроется DevTools фонового процесса (там видны ошибки и логи).
2. Войдите в ChatGPT и Claude в обычных вкладках.
3. В `chrome://settings/downloads` отключите «Всегда указывать место для скачивания».
4. После каждой операции сверяйте журнал (Настройки → Журнал операций).
5. Целостность файлов на диске: `node tools/verify-backups.mjs ~/Downloads/ChatBackups`.

### Дополнительные проверки

- **Полнота против неполноты.** Откройте `chat.meta.json`: `completeness.status`, список
  `checks` и `integrity` (`totalNodes`, `pathLength`, `brokenLinks`, `crossCheckMissing`).
  У неполного экспорта в HTML/PDF есть красный блок «Экспорт неполный», в MD — предупреждения
  в начале, в имени файла — суффикс `_НЕПОЛНЫЙ`.
- **Отсутствие внешних загрузок.** Откройте `chat.html` без сети: всё отображается, в DevTools
  на вкладке Network нет запросов (CSP документа запрещает скрипты и любые загрузки).
- **Кириллица в PDF.** Названия, текст и таблицы читаются; текст выделяется и ищется.
- **Изменение интерфейса сервисов.** Если в журнале появились `BAD_RESPONSE` или «формат API
  изменился», адаптер устарел: обновите `src/adapters/<service>/normalize.js` и клиент в
  `src/content/`.
