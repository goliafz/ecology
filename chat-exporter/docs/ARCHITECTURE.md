# Архитектура Chat Exporter

Документ описывает анализ вариантов, ограничения платформы и итоговое устройство расширения.
Пометки: **[проверено]** — подтверждено документацией, исходным кодом Chromium или запуском в
Chromium; **[предположение]** — опирается на сторонние открытые проекты и может устареть.

## 1. Сравнение способов экспорта

### Вариант A. Прокрутка страницы

Расширение прокручивает контейнер переписки от начала до конца и собирает сообщения.

- **Полнота.** Гарантировать её нельзя. Признак «все сообщения загружены» приходится выводить
  косвенно: позиция прокрутки дошла до края и несколько итераций подряд не появляется ничего нового.
- **Виртуализированный DOM.** Сообщения вне экрана удаляются из DOM, поэтому собирать их нужно
  по ходу прокрутки и склеивать фрагменты. Склейка по тексту ломается на одинаковых сообщениях
  («ок», «продолжай»), склейка по позиции — на подгрузке. Рабочий вариант — выравнивание
  последовательностей по ключам (id, если страница его отдаёт, иначе роль + хеш текста) с
  обязательным перекрытием соседних снимков. Нет перекрытия — значит, возможен пропуск.
- **Зависания и смена вёрстки.** Нужны тайм-ауты, ожидание «тишины» DOM (MutationObserver) и
  набор запасных селекторов. После обновления сайта селекторы всё равно приходится чинить.
- **Скорость.** Низкая: сотни сообщений — это десятки шагов прокрутки с ожиданием рендера.

### Вариант B. Извлечение из DOM без прокрутки

Быстро и просто, но видит только то, что сейчас отрендерено. На длинных и виртуализированных
чатах получится неполный результат без надёжного способа это заметить. Разметка — не API:
классы и `data-*` меняются без предупреждения. Восстановление Markdown из HTML всегда
приблизительное (KaTeX, кнопки «Copy», подписи языков у блоков кода).

### Вариант C. Комбинированный (DOM + прокрутка)

Это вариант A, доведённый до ума: прокрутка к началу до стабилизации, затем шаги вниз по 70 %
высоты окна, снимок на каждом шаге и выравнивание снимков. Механизм полноты:

1. `reachedTop` — дошли до начала, и первый ключ не меняется две итерации подряд;
2. `reachedBottom` — дошли до конца после финального ожидания;
3. `snapshotGaps` — сколько снимков не удалось выровнять с уже собранной последовательностью;
4. проверка, что ответ не генерируется в этот момент.

Любое нарушение делает экспорт **неполным**. Реализовано в `src/content/dom-extract.js` и
`src/core/snapshot-merge.js`. В Chromium проверено на виртуализированном списке из 60 сообщений,
где в DOM одновременно находится около 9, а пары одинаковых «Ок» повторяются 6 раз: собраны все
60 сообщений в правильном порядке.

### Вариант D. Другие способы

| Способ | Что даёт | Ограничения |
|---|---|---|
| Официальный экспорт ChatGPT (Настройки → Управление данными → Экспорт) | Архив со всеми чатами | Ссылка приходит на почту, доставка до 7 дней, ссылка живёт 24 часа; для Business/Enterprise недоступно. Автоматизировать нельзя. **[проверено: справка OpenAI]** |
| Официальный экспорт Claude (Настройки → Конфиденциальность → Экспорт данных) | Архив со всеми чатами | Ссылка на почту, живёт 24 часа. Автоматизировать нельзя. **[проверено: справка Anthropic]** |
| Сохранение исходного HTML страницы | Снимок того, что видно | Видимая часть, скрипты, внешние ресурсы. Полноты нет |
| **Данные веб-приложения** — те же JSON-запросы, которые делает сам сайт, выполненные во вкладке пользователя | Полное дерево сообщений с id, родителями, временем и исходным Markdown, без прокрутки | Эндпоинты внутренние и недокументированные **[предположение: структура взята из открытых проектов]**. Могут измениться в любой момент |

Публичного API для истории чатов веб-версии нет ни у ChatGPT, ни у Claude. Платные API
(OpenAI API, Anthropic API) — это другие продукты, переписки из веб-интерфейса через них недоступны.

**Про допустимость.** Расширение не обходит авторизацию. Запросы выполняются content
script'ом в уже открытой вкладке пользователя, с куками этой вкладки, теми же эндпоинтами,
которые сайт вызывает при открытии чата. Пароли и токены никуда не передаются и не хранятся
(токен ChatGPT живёт в памяти вкладки до 10 минут). Перед использованием проверьте условия
использования сервисов: автоматизированный доступ может ими ограничиваться.

### Сводная оценка

| Критерий | A. Прокрутка | B. DOM | C. DOM + прокрутка | D. Данные веб-приложения |
|---|---|---|---|---|
| Полнота | средняя | низкая | высокая, проверяемая | **максимальная, проверяемая** (цепочка parent-id) |
| Надёжность | средняя | низкая | средняя | высокая, пока не изменился формат |
| Скорость | низкая | высокая | низкая | **высокая** (1 запрос на чат) |
| Сложность | высокая | низкая | высокая | средняя |
| Устойчивость к редизайну | низкая | низкая | низкая | **высокая** (вёрстка не важна) |
| Устойчивость к смене API | — | — | — | низкая (нужно обновлять адаптер) |
| Риск блокировки | низкий | низкий | низкий | низкий при умеренной частоте; есть паузы и обработка 429 |
| Ограничения Chrome | нужна открытая вкладка с чатом | то же | то же | нужна любая вкладка сервиса |
| Автоматический режим | только с открытием каждого чата | нет | только с открытием каждого чата | **да, без открытия чатов** |
| Поддержка | селекторы | селекторы | селекторы + склейка | разбор JSON в одном адаптере |

### Рекомендация

**Основной путь — D (данные веб-приложения), резервный — C (DOM + прокрутка).**

- D даёт исходный Markdown без конверсии, точный порядок по дереву, id сообщений и время.
  Полноту можно проверить формально: цепочка от последнего узла к корню без разрывов.
- D позволяет получать список чатов со временем изменения — на этом построен автоматический
  режим без открытия сотен вкладок.
- C включается, только если данные недоступны (изменился формат, ошибка сервера) и чат открыт
  во вкладке. Результат помечается предупреждением «резервный режим».
- В режиме D дополнительно сверяется открытая страница: id сообщений в DOM ChatGPT должны
  входить в выгрузку (у Claude — число сообщений пользователя).

## 2. Ограничения Chrome и сайтов

| Ограничение | Факт | Как учтено |
|---|---|---|
| Жизненный цикл service worker | Останавливается через 30 с бездействия; событие или вызов API сбрасывает таймер; один запрос не дольше 5 минут; активная сессия `chrome.debugger` держит worker живым (Chrome 118). **[проверено: документация]** | Состояние очереди в `chrome.storage.local`; во время работы раз в 20 с вызывается API; тайм-аут операции во вкладке до 4,5 мин; после перезапуска задания возвращаются в очередь |
| `chrome.alarms` | Минимальный период 30 с. Будильники «обычно сохраняются до обновления расширения», но «могут быть удалены при перезапуске браузера». Поведение во сне «не определено», будильник может сработать «значительно позже». С Chrome 150 есть `persistAcrossSessions`. **[проверено: документация, @types/chrome]** | Время следующего запуска хранится в storage и будильник пересоздаётся при каждом старте. Сработавший с опозданием больше 15 минут считается пропущенным запуском |
| Закрытый браузер | Код расширения не выполняется, если Chrome закрыт или компьютер выключен | Догоняющий запуск при следующем старте: автоматически / спросить / пропустить |
| `chrome.downloads` | Путь только относительно папки «Загрузки», подпапки разрешены, абсолютные пути и `..` — ошибка. **[проверено]** Каждый компонент проходит `net::IsSafePortableRelativePath` (запрещены `"*/:<>?\|`, управляющие символы, пробелы и точки по краям, зарезервированные имена Windows). **[проверено: исходники Chromium]** | `sanitizeSegment`, `isSafeRelativePath` |
| Кириллица в именах | На Linux с не-UTF-8 локалью Chrome отвергает не-ASCII имена ошибкой `Invalid filename`; с UTF-8 работает. **[проверено запуском]** | Автоматический повтор с транслитерированным путём |
| «Всегда указывать место для скачивания» | Если настройка включена, Chrome показывает диалог и для загрузок расширений (`saveAs:false` не отменяет настройку пользователя). **[проверено: download_target_determiner.cc]** | Предупреждение в настройках; тайм-аут с подсказкой |
| Перезапись | `conflictAction: 'overwrite' \| 'uniquify'`. Chrome пишет во временный файл и переименовывает его по завершении. **[проверено: документация]** | Прерванная загрузка не портит старую копию; `meta.json` пишется последним |
| Blob в service worker | В worker нет `URL.createObjectURL`; offscreen-документ с причиной `BLOBS`; в offscreen доступен только `chrome.runtime`; одновременно один offscreen-документ. **[проверено]** | `src/offscreen/` |
| PDF | `Page.printToPDF` через `chrome.debugger`; разрешение `debugger` **нельзя** сделать опциональным (флаг `kFlagCannotBeOptional`), оно подразумевает доступ ко всем сайтам; при подключении Chrome показывает полосу «…начало отладку этого браузера». Подключение к страницам **своего** расширения разрешено. **[проверено: исходники Chromium]** | Печать своей страницы `print.html`. Альтернатива без автоматизации — окно печати |
| File System Access API | `showDirectoryPicker` требует жеста пользователя и окна; разрешение на папку после перезапуска браузера обычно нужно подтверждать снова **[предположение]**; в service worker окна нет | Не используется: для фонового копирования ненадёжно |
| Внутренние эндпоинты сайтов | Не документированы, могут измениться | Адаптеры изолированы; при ошибке формата — резервный DOM-режим и понятное сообщение |
| Вход в аккаунт | Без авторизованной сессии данных нет | Ошибка `NOT_AUTHENTICATED`, автоповтор не делается до следующего запуска |
| Частота запросов | Сервис может вернуть 429 | Последовательная очередь, пауза 2,5 с + случайная добавка, `Retry-After`, общая пауза очереди |

### Почему не File System Access API

| | `chrome.downloads` (выбран) | File System Access API |
|---|---|---|
| Работа в фоне | да, из service worker | нет: нужна страница и жест пользователя |
| Выбор произвольной папки | нет, только внутри «Загрузок» | да |
| Перезапуск браузера | без повторных разрешений | разрешение, как правило, нужно подтверждать снова |
| Чтение записанного | нет | да |

Для ежедневного автоматического копирования надёжность важнее свободы выбора папки. Чтобы
копии лежали в другом месте, можно перенести папку «Загрузки» в настройках Chrome или сделать
символическую ссылку `Загрузки/ChatBackups` → нужная папка (облачная, внешний диск).

### Конвейер экспорта одного чата (`exporter.js`)

1. Вкладка сервиса: активная (ручной экспорт), любая существующая или фоновая новая (авто).
2. `fetchChat` в content script → сырой JSON и изображения (data: URL, лимит размера).
3. Адаптер сервиса нормализует JSON в `NormalizedChat` (`src/core/model.js`).
4. При ошибке формата или сервера, если чат открыт во вкладке, — резервный DOM-режим.
5. `evaluateCompleteness` → `complete` / `complete_with_warnings` / `incomplete`.
6. Хеш содержимого (без времени выгрузки, подписанных URL и байтов картинок). Не изменился —
   файлы не трогаются, дописываются только недостающие форматы.
7. Защита от отката: если сервис отдал версию старее сохранённой, файлы не перезаписываются.
8. Неполный автоматический экспорт ничего не пишет и ставится на повтор. Неполный ручной
   записывается с суффиксом `_НЕПОЛНЫЙ` и пометкой внутри документа.
9. Запись MD → HTML → PDF, затем `*.meta.json` с SHA-256 и размерами файлов.
10. Обновление индекса чата.

### PDF в фоновой вкладке

Страница печати открывается неактивной вкладкой. В фоновых вкладках Chrome приостанавливает
`requestAnimationFrame` (MDN) и может откладывать декодирование изображений, поэтому:
- страница печати не ждёт кадров отрисовки, а все её ожидания ограничены по времени;
- отладчик подключается к пустой вкладке до загрузки страницы и включает
  `Emulation.setFocusEmulationEnabled`, чтобы вкладка вела себя как видимая;
- если сообщение «готово» потерялось, готовность проверяется через `Runtime.evaluate`.
Версия 1.1.1 ждала кадр отрисовки и в фоновой вкладке зависала на 90 секунд.

### Особые случаи формата ChatGPT

- **Блоки кода как виджеты.** В `metadata.content_references` ChatGPT отмечает куски текста.
  Маркеры цитат обёрнуты в символы из частной области Unicode (`\uE200…\uE201`) и заменяются
  ссылкой (`alt`). Но там же бывают ссылки типа `client_defined_widget` (`widget_type: code_block`),
  у которых `matched_text` — это целый блок кода ответа, а `alt` пуст. Такие куски нужно оставлять
  как есть. В версиях 1.0.0–1.1.0 очистка цитат вырезала их, и ответ, состоящий из одного блока
  кода, пропадал. Это подтверждено файлом диагностики реального чата и исправлено в 1.1.1.
- **Канал `analysis`.** У моделей с рассуждениями скрытые рассуждения, по-видимому, приходят
  сообщениями с `channel: "analysis"` **[предположение]**. Они не выдаются за ответ и попадают
  в документ только при включённой настройке «размышления модели».
- **Холст (canvas).** Документ холста приходит вызовом `canmore.create_textdoc` с JSON
  `{name, type, content}`, правки — `canmore.update_textdoc` **[предположение: формат взят из
  открытых источников и на реальных данных не проверялся]**. Адаптер собирает из этого документ.

Защита от потери ответа в незнакомом формате (три уровня):
1. Если ход модели не дал видимого содержимого, но в его сообщениях есть текст, текст сохраняется
   как есть, с пометкой «формат не распознан». Статус — «с предупреждениями».
2. Если в ветке есть ответ, а документ заканчивается вопросом, статус «НЕПОЛНЫЙ».
3. Сверка с открытой страницей идёт по идентификаторам сообщений, которые реально сохранены или
   намеренно скрыты.

Именно уровень 1 сработал в 1.1.0 на чате с блоком-виджетом: ответ сохранился, но с ложными
предупреждениями. Кнопка «Данные для диагностики» сохраняет исходный JSON чата и снимок структуры
страницы (теги и атрибуты возле первого сообщения, без текста), чтобы разбирать такие случаи.

### Идентификация

- Чат: `service:id`, где id — UUID сервиса (из URL и данных).
- Сообщение: id сервиса (ChatGPT `message.id`, Claude `uuid`). Порядок — по ссылкам на
  родителя от текущего листа (`current_node` / `current_leaf_message_uuid`), а не по тексту.
  Одинаковые тексты не путаются, правки и перегенерации видны как ветки: экспортируется
  текущая ветка, в документе отмечено «версия 2 из 3».
- DOM-режим: id из `data-message-id` (ChatGPT) или роль + FNV-хеш текста (Claude) с
  выравниванием последовательностей.

### Что где хранится

| Ключ | Хранилище | Переживает перезапуск | Содержимое |
|---|---|---|---|
| `settings` | storage.local | да | настройки |
| `chatIndex` | storage.local | да | по каждому чату: название, папка, время изменения, последний экспорт (хеш, статус, файлы с SHA-256), ошибки, метка активности |
| `queue` | storage.local | да | задания и текущий запуск |
| `schedule` | storage.local | да | следующий запуск, последний запуск, пропущенный запуск |
| `log` | storage.local | да | журнал (до 500 записей, можно выключить и очистить) |
| `listCache:*`, `selection`, `lastResult` | storage.local | да | кеш списков, выбранные чаты, последний результат |
| `openedTabs` | storage.session | нет (нужен только в рамках сессии) | вкладки, открытые расширением |

Текст переписок в хранилище расширения не сохраняется — только метаданные.

### Защита от сбоев

| Риск | Защита |
|---|---|
| Повторный экспорт | хеш содержимого + время изменения; ручной экспорт пишет всегда |
| Дублирование сообщений | путь по дереву id; проверка уникальности id |
| Пропуск сообщений | проверка цепочки родителей; сверка с DOM; в DOM-режиме — перекрытие снимков и края |
| Границы чата | id из URL; DOM-режим запускается, только если во вкладке открыт именно этот чат |
| Изменения DOM | основной путь не зависит от вёрстки; селекторы с запасными вариантами |
| Повреждение файлов | временный файл Chrome + сверка размера; SHA-256 в `meta.json`; `tools/verify-backups.mjs` |
| Зацикливание очереди | лимит попыток, экспоненциальная пауза, после исчерпания чат ждёт нового изменения; лимит чатов за запуск |
| Перезапуск worker | очередь и расписание в storage; `running` → `pending` при старте |
| Закрытие вкладки во время работы | аренда вкладок: открытые расширением вкладки закрываются, только когда их никто не использует |

## 4. Автоматическое резервное копирование

- **Сценарий A (расписание).** Будильник на время из настроек (дни недели — опционально).
  Список чатов → кандидаты: новые (изменены после включения режима), изменённые после
  последнего экспорта, отмеченные активностью, неполные, на повторе. Последовательная очередь.
- **Помеченные чаты (по умолчанию).** База `tracked` в `chrome.storage.local` с ключом
  `service:id`; id берётся из адреса чата и совпадает с id в данных сервиса. Галочка «Сохранять» в
  окне расширения добавляет чат в базу. Значок у каждой вкладки свой (`chrome.action.setIcon` с
  `tabId`): зелёный — чат в базе, красный — нет. Обновляется по `tabs.onUpdated` (в том числе при
  переходах внутри страницы, когда меняется адрес) и `tabs.onActivated`. Пути к иконкам — от корня
  расширения: относительный путь в service worker разрешается от папки скрипта, и `setIcon`
  падает с «Failed to fetch» (проверено в Chromium). В автоматическом запуске кандидаты
  фильтруются по базе; помеченный, но ни разу не сохранённый чат добавляется, даже если его нет в
  укороченном списке.
- **Сценарий B (переключатель «Авто»).** Включает расписание. Чаты не открываются по одному:
  изменения видны из списка (у ChatGPT он отсортирован по времени изменения, поэтому список
  читается только до времени прошлого запуска минус сутки). Удалённые и архивированные чаты
  отмечаются в индексе, файлы не удаляются. Переименование не создаёт новую папку.
  Недоступный чат (404/403) больше не повторяется, пока снова не изменится.
- **Сценарий C (отметки во время работы).** Content script не реагирует на каждое изменение
  DOM. Чат отмечается только после 15 секунд тишины, если ответ не генерируется и изменилось
  число сообщений или последнее сообщение, и не чаще раза в минуту на чат. Передаются только
  id и название. Отметка гарантирует попадание чата в вечернюю очередь, даже если список
  получить не удалось. По сравнению с обходом списка это дешевле и надёжнее для активных
  чатов, но видит только работу в этом браузере. Поэтому используются оба механизма.
- **Сценарий D (догоняющий запуск).** При старте сравниваются `nextRunAt` и `lastRunStartedAt`.
  Пропуск обрабатывается по настройке; повторной обработки нет, потому что выбор кандидатов
  основан на индексе (хеш + время изменения).
- **Первый запуск.** Чтобы включение режима не запустило выгрузку сотен старых чатов,
  сохраняются только чаты, изменённые после включения. Старые — по флажку «постепенно сохранить
  старые чаты», не больше N за запуск (по умолчанию 100).

JavaScript (ES2022, ES-модули) с JSDoc-типами, проверяемыми `tsc --checkJs`. Расширение
